# Scheduled task: SendFair daily rate check

- Schedule: daily 09:37 and 19:37 Nairobi (`CRON_TZ=Africa/Nairobi 37 9,19 * * *`); the evening run is a backup
- Model: claude-opus-5-5 · approval: automatic · notifications: push
- Needs: the owner's computer on with the Claude desktop app open (it uses the built-in browser), plus Claude Code Remote (add_repo)
- Each run starts a fresh session. To recreate on another account, create a scheduled task with this schedule and the prompt below, word for word.

## Prompt

You run the rate check for SendFair, a money-transfer comparison website owned by the user (GitHub repo malayic4-eng/sendfair; live at https://sendfair.africa; Cloudflare redeploys on every push to main). The user is not technical. Read today's rates from each provider's own public website, update data/quotes.json, and publish. Never invent or estimate a rate, fee or delivery time.

This task runs twice a day (09:37 and 19:37 Nairobi). The evening run is a backup: after cloning, if data/quotes.json "updatedAt" is less than 9 hours old, today's check already ran, so stop without changing anything or sending a report.

SETUP
1. add_repo (owner malayic4-eng, repo sendfair, access push), then git clone --depth 1 https://github.com/malayic4-eng/sendfair. git config user.name Claude; git config user.email noreply@anthropic.com. End every commit message with the attribution lines from your session instructions.
2. Use the built-in browser in the user's Claude desktop app (tools mcp__remote-devices__Claude_Browser__*; if only enable__mcp__remote-devices__Claude_Browser exists, call it first; load all of them in one ToolSearch with query "mcp__remote-devices__Claude_Browser__"). Load the built-in-browser skill if listed. If the browser cannot be reached, change nothing: send one short message that the computer or desktop app was offline so this check was skipped (and, for the morning run, that the 19:37 run will try again), and stop.
3. Allowed sites: wise.com, remitly.com, worldremit.com, westernunion.com, sendwave.com, taptapsend.com, and (Mondays only, for ratings) trustpilot.com. Do not call providers' APIs directly; load their public pages and read what the page shows (javascript_tool reading document.body.innerText is fine). Use browser_batch with at most 4 page loads per batch (each batch must finish within ~50 s). Keep each javascript call under ~30 s.

ROUTES (24) and reference amounts: senders us (USD 300), uk (GBP 250), canada (CAD 400), australia (AUD 450) x receivers nigeria NGN, ghana GHS, kenya KES, uganda UGX, zambia ZMW, zimbabwe (pays USD). Route key = sender-receiver, e.g. uk-nigeria.

PROVIDERS
- Wise (exact fee from two readings): for each route load https://wise.com/{us|gb|ca|au}/currency-converter/{src}-to-{tgt}-rate?amount=A twice, with A = the reference amount and A = 4 x the reference amount. Wait 4 s. In the page text, after "Recipient gets", find "Wise N CUR" (Wise is not always listed first) and read N; also read the mid-market heading "1 GBP = 1,862 NGN" (use the most precise figure shown, e.g. a 4-decimal "15.4907" when present). With g1 at A1 and g2 at A2: k = (g2-g1)/(A2-A1); feeFixed = round(A1 - g1/k, 2); feePct = round((mid/k - 1)*100, 2); rate = mid; refAmount = A1. Note "Fee read at two amounts from Wise's calculator: fixed part plus a percentage". If there is no Wise figure (e.g. ZMW), Wise does not send there. Payout: nigeria ["bank"], ghana/kenya ["mobile","bank"], uganda ["bank"]. Also read gbp-to-usd, cad-to-usd, aud-to-usd mid rates.
- Remitly: https://www.remitly.com/{us|gb|ca|au}/en/currency-converter/{src}-to-{tgt}-rate . Wait 3 s, read text after "They receive". Use "Standard rate 1 X = Y" or "Everyday rate 1 X = Y". NEVER use "Welcome rate". If only a welcome rate is shown, skip. Fee = the "Fee N" value (before any "Fee discount"), or 0 for "Zero fees". Payout ["mobile","bank","cash"]. Note "Standard rate; new-customer offers not included". No Zimbabwe calculator: skip.
- Western Union: https://www.westernunion.com/{us|gb|ca|au}/en/currency-converter/{src}-to-{tgt}-rate.html (skip zimbabwe: the USD converter is not specific to Zimbabwe). Wait 3.5 s, read "FX: 1.00 X – Y" and "Fee: F", and the first input value (the amount the fee applies to; store that as refAmount). Payout ["cash","bank"]. Note "From Western Union's online converter; may vary by payment and payout method". If the site blocks navigation, skip the rest of Western Union.
- Sendwave: https://www.sendwave.com/{en-gb|en-us|en-ca}/countries/{receiver} (not Australia). Read "Exchange Rate: 1 X = Y" and "Transfer fees: F". If the rate shows "_" the route is not offered: skip. If "Intro Rate Discount: 1 X = AB" appears, the standard rate is the FIRST of the two run-together numbers (e.g. "169.444170.303" -> 169.444); never use the intro rate. Payout: nigeria ["bank"], ghana ["mobile"], kenya/uganda ["mobile","bank"], zambia ["mobile"], zimbabwe ["mobile"]. Note "Standard rate; intro offers not included".
- Taptap Send: https://www.taptapsend.com/en . Native selects #origin-currency (values like GB-GBP-ORIGIN) and #destination-currency (NG-NGN-DESTINATION, GH-GHS, KE-KES, UG-UGX, ZM-ZMW). Set value + dispatch change, wait 1.3 s, read "Today's rate:GBP 1 = Y". "No transfer fees" = fee 0. Taptap does not serve Zimbabwe. Payout: nigeria ["bank","mobile","cash"], ghana/kenya ["mobile","bank"], uganda/zambia ["mobile"].
- WorldRemit: https://www.worldremit.com/en/{receiver} (and /en-au/, /en-ca/ for those senders). Never use a "First Transfer Rate" (a promotion). Only if the page's default sending currency matches the route and no "First Transfer" text appears, record the rate, Fee, Transfer time and Receive method (variant). Otherwise leave existing WorldRemit quotes untouched.

DELIVERY TIME (speed field): whenever a provider's page shows a delivery estimate for the route (e.g. WorldRemit "Transfer time ⚡ Within 5 minutes", Remitly "Express"/"minutes"/"days", any "arrives in" text), store it as a short phrase such as "Within minutes", "Within 1 hour", "Same day" or "1–2 working days". Only record what the page shows for that route; leave speed empty otherwise. Generic marketing text like "send in seconds" does not count.

SANITY CHECK: compute each route's mid-market from today's Wise mids (per-USD rates: rates[tgt]/rates[src]; USD=1). Reject any rate >2% above or >12% below mid; mention rejects in the report.

WRITING DATA
- data/quotes.json: {"updatedAt", "coverage": {route: [all provider ids]}, "quotes": {route: [quote]}}. Quote fields: provider, variant (optional), rate, feeFixed, feePct, payout, speed, note, refAmount, checkedAt (ISO UTC when read). Provider ids: wise, worldremit, remitly, sendwave, lemfi, taptapsend, afriex, nala, africhange, mukuru, westernunion, moneygram.
- Replace a provider's quotes on a route only with values read today. Leave quotes you could not re-read untouched (the site marks old ones stale and hides them after 72 h).
- data/mid-overrides.json: first move the file's current "updatedAt" and "rates" into a "previous" key ({"updatedAt": ..., "rates": {...}}; the site shows the change since then next to the market rate). Then set "updatedAt": now, "source": "Mid-market rates shown on wise.com", "rates": {USD: 1, NGN, GHS, KES, UGX, ZMW, GBP, CAD, AUD per 1 USD} (keep the existing ZMW if Wise shows no ZMW rate).
- Mondays only (morning run): open https://www.trustpilot.com/review/{domain} for wise.com, remitly.com, worldremit.com, sendwave.com, taptapsend.com, westernunion.com and update data/ratings.json (score, label such as "Excellent", review count, checkedAt) only with what the page shows. Leave an entry unchanged if its page can't be read.
- Run node scripts/record-history.mjs (it stores today's best amounts for the rate-history charts and alerts; it needs no arguments).
- node scripts/build.mjs (fix any data error it prints), git pull --rebase, commit "Daily rate check <date>", push.

REPORT (user reads it on a phone): how many routes and quotes were updated, the top provider and amount for UK to Nigeria, US to Kenya and UK to Ghana (if services tie, name them all), anything skipped and why. Then a ready-to-paste WhatsApp post: "SendFair rates today, <date>. Most money home for a typical transfer:" one line per route for uk-nigeria, us-nigeria, uk-kenya, us-kenya, uk-ghana, us-ghana, canada-nigeria, uk-zimbabwe like "UK → Nigeria (GBP 250): <provider>, NGN <amount>" (for a tie: "<A> and <B> tie, NGN <amount>"), then the link https://sendfair.africa
